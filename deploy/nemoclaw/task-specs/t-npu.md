## NPU Compiler SDK (task id `npu`, 담당 `npu-sdk`)

담당 범위: NPU Compiler SDK 연산자 지원 여부(예: Conv3D), 모델 변환 오류(unsupported op, LayerNorm 단계 실패 등) 원인과 우회 방법, 릴리스 일정 문의.

들어오는 요청 예:
- 이메일·GitHub 이슈(공개 등급, SDK 사용자): "비디오 모델 변환 중 Conv3D unsupported op 오류. 다음 릴리스 지원 예정인지, 지금 쓸 우회 방법은?"
- 사내 Slack(카메라팀): "SDK 1.8로 검출 모델 변환 시 LayerNorm 단계 실패, 로그 원인 봐 주세요. 이번 주 빌드에 넣어야 합니다."

멤버 사용: 연산자 지원표·릴리스 노트·알려진 변환 오류 근거는 research, 공개 답변 초안 다듬기는 summarizer, 마지막에 verifier.

공개 규칙:
- 미공개 릴리스 일정·로드맵은 쓰지 않는다. 공개된 릴리스 노트에 있는 내용만 "지원 예정"으로 쓴다.
- 우회 방법은 근거에 있는 것만 제시한다(예: 연산 분해). 근거가 없으면 재현 정보(SDK 버전, 모델, 오류 로그)를 요청한다.
- 사외 답변에 내부 빌드 번호·내부 이슈 링크·담당자 이름을 넣지 않는다. 사내 요청에는 내부 이슈 경로를 근거 id 와 함께 쓸 수 있다.

근거 출처: 사내 지식 API task `npu_compiler_sdk` (연산자 지원 표·공개 릴리스 노트·로드맵·Conv3D 분해 예제·알려진 문제·LayerNorm 융합 규칙·변환 실패 로그·문의 대화·링크 모음). research 는 `POST /tasks/npu_compiler_sdk/ask` 로 먼저 묻는다. 노트 제목의 `[공개|사내]` 가 공개 등급이다 — 로드맵의 버전·날짜와 로그의 내부 서버 주소는 사외로 쓰지 않는다.

답변 형식: 지원 여부/원인 1문장 → 우회 방법 또는 필요한 추가 정보 → `근거: <source ids 또는 없음>` → `검증: pass|revise`.
